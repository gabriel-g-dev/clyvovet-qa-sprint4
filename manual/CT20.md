**Pré-condições:** API .NET no commit e80bfc05e203944054c4ab3f43eb4e6f5a098426, SDK 9; origem http://localhost:5109. Usar Oracle 21 com schema exclusivo e migration 20261025155040_OracleBaseline aplicada previamente, conforme README da versão fixada; não aplicar scripts legados ou migrations em banco compartilhado. MongoDB de QA disponível em banco descartável próprio. Configurar somente na sessão ConnectionStrings__OracleConnection, Mongo__ConnectionString e Mongo__DatabaseName. Credenciais sintéticas exclusivas desse ambiente: Auth__Username=qa-admin, Auth__Password=QaLocal123!, Auth__SigningKey=QaOnlySigningKey_ClyvoVet_2026_32_chars. Não são credenciais de produção. POST /api/auth/login devolve accessToken e tokenType=Bearer; todas as rotas de negócio exigem Authorization: Bearer `<accessToken>` com scope=clinical. Usar Content-Type application/json. Não registrar tokens, chave real ou connection strings nas evidências. Registrar D em UTC e calcular D-1/D+30 antes de iniciar. Capturar IDs das respostas; request de pet usa tutorId, resposta usa donoId. As listagens principais são paginadas em data/page/pageSize/totalItems/totalPages; não confundir com os arrays das rotas adicionais.

**Entradas controladas:** Login username=qa-admin,password=QaLocal123!; tutor nome=Tutor QA20,email=qa20@example.test,telefone=(11)90000-0020; pet QA-NET20,Cachorro,SRD,2023-01-15T00:00:00,peso=12.5,tutorId=idTutor; nome editado QA-NET20-editado
