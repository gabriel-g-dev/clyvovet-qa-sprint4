# CT26 — .NET valida histórico clínico, evolução documental e score do pet

**Objetivo:** Validar os sete recursos relacionais e o registro/leitura de evolução clínica documental do mesmo pet, sem presumir integração com Java ou Mobile.

**Azure:** [CT26 · #88](https://dev.azure.com/clyvovet-fiap-2026-rm563298/ClyvoVet/_workitems/edit/88) · [PBI #16](https://dev.azure.com/clyvovet-fiap-2026-rm563298/ClyvoVet/_workitems/edit/16). Origem: Sprint 1; regressão do release na Sprint 4.

**Pré-condições:** API .NET no commit e80bfc05e203944054c4ab3f43eb4e6f5a098426, SDK 9; origem http://localhost:5109. Usar Oracle 21 com schema exclusivo e migration 20261025155040_OracleBaseline aplicada previamente, conforme README da versão fixada; não aplicar scripts legados ou migrations em banco compartilhado. MongoDB de QA disponível em banco descartável próprio. Configurar somente na sessão ConnectionStrings__OracleConnection, Mongo__ConnectionString e Mongo__DatabaseName. Credenciais sintéticas exclusivas desse ambiente: Auth__Username=qa-admin, Auth__Password=QaLocal123!, Auth__SigningKey=QaOnlySigningKey_ClyvoVet_2026_32_chars. Não são credenciais de produção. POST /api/auth/login devolve accessToken e tokenType=Bearer; todas as rotas de negócio exigem Authorization: Bearer `<accessToken>` com scope=clinical. Usar Content-Type application/json. Não registrar tokens, chave real ou connection strings nas evidências. Registrar D em UTC e calcular D-1/D+30 antes de iniciar. Capturar IDs das respostas; request de pet usa tutorId, resposta usa donoId. As listagens principais são paginadas em data/page/pageSize/totalItems/totalPages; não confundir com os arrays das rotas adicionais.

Consulta: tipo=Rotina,valor=180,descricao=Consulta sintética QA26,status=A,data=D-1T10:30:00,petId=idPet,funcionarioId=idFuncionario. Vacina: nome=Vacina QA26,data=D+30T00:00:00,status=P,petId=idPet. Prescrição: consultaId=idConsulta,medicamentoId=idMedicamento,dosagem=QA-DOSE-26 (texto sintético). Edições: consulta status=R, vacina status=A e data=D-1T00:00:00, dosagem=QA-DOSE-26-editado; demais campos preservados; Evolução: {"texto":"Evolução sintética QA26","tags":["qa26","retorno"]}; banco MongoDB descartável QA_CT26_UUID, nome registrado antes do teste.

**Saída esperada:** Login 200; criações relacionais 201 com id e Location; pet responde donoId=idTutor, consultas e vacinas de QA. Prescrição contém os ids, medicamentoNome=Medicamento QA26 e dosagem sintética. Evolução criada 201 com GUID de 32 caracteres, petId=idPet, texto e tags exatos, autor=qa-admin e registradoEmUtc no intervalo da chamada; consulta paginada pela tag qa26 contém uma evolução. PUTs relacionais=200; exclusões relacionais=204 e GETs posteriores=404. Evoluções são imutáveis e sua limpeza exige descarte do banco MongoDB QA, não um DELETE inexistente na API. Inteligência .NET retorna score 80 antes da consulta R e 100 depois, ambos EXCELENTE conforme o contrato próprio da .NET.
