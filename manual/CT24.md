# CT24 — Mobile mantém pets e isola dados entre duas contas

IDENTIFICAÇÃO: CT24 — Mobile mantém pets e isola dados entre duas contas

OBJETIVO: Verificar CRUD persistente e RLS de pets.

RASTREABILIDADE: PBI #31 (https://dev.azure.com/clyvovet-fiap-2026-rm563298/ClyvoVet/_workitems/edit/31). Funcionalidade planejada na Sprint 3; regressão/validação no release Sprint 4, entrega 04/11/2026.

PRÉ-CONDIÇÕES: App no commit bef537c, Expo Go e projeto Supabase exclusivo de QA com schema.sql aplicado uma vez. Duas contas confirmadas: qa.a@example.test e qa.b@example.test, senha pública de teste QaMobile123!; cadastrar por Auth local ou confirmação desabilitada somente no projeto QA. Nunca usar a URL compartilhada do README para criar dados sem confirmar que é ambiente descartável. UUIDs são capturados das respostas, não adivinhados.

ENTRADAS CONTROLADAS: QA A e QA B; pet nome=QA-MOB24,especie=Cachorro,raca=SRD,idade=3; edição nome=QA-MOB24-editado,idade=4; peso e dataNascimento não são campos do app

SAÍDA ESPERADA: A cria, consulta e edita seu pet após reload; B não vê nem altera o UUID de A; exclusão por A remove somente seu pet.

PASSOS:
1. Entrar com QA A e cadastrar QA-MOB24, Cachorro, SRD, idade 3.
   Esperado: Pet aparece em Pets; capturar UUID_A no Supabase QA.
2. Editar nome para QA-MOB24-editado e idade para 4; fechar e reabrir app.
   Esperado: Nome/idade persistem sem novo cadastro.
3. Sair, entrar como QA B e abrir Pets.
   Esperado: Pet de A ausente.
4. Com JWT de B, no Supabase QA, consultar /rest/v1/pets?id=eq.UUID_A e tentar PATCH nome=INDEVIDO.
   Esperado: Consulta retorna []; alteração não modifica o pet de A (representação vazia ou erro de RLS).
5. Voltar como A, conferir nome e excluir o pet QA.
   Esperado: Nome permanece QA-MOB24-editado; exclusão remove a linha e persiste após reload.

CRITÉRIO DE APROVAÇÃO: Aprovar somente se todos os resultados de cada passo forem observados; qualquer divergência reprova o caso.

RESTAURAÇÃO: Remover apenas os registros QA criados no ambiente de teste; restaurar os serviços interrompidos.

EXECUÇÃO: Planejado. Execução manual não realizada. Resultados da automação, quando disponíveis, são evidências separadas.

OBSERVAÇÕES: O token deve ser usado apenas no cliente local; não colar JWT em Boards, GitHub nem gravações. Não confundir RLS com filtro na interface.
